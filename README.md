# Форма регистрации — решение группы 2

Учебная форма регистрации на чистом HTML, CSS и JS, без сборки и зависимостей. В ней три поля: телефон, пароль и повтор пароля.

Это ветка группы 2 семинара по поиску и исправлению багов. Исходный репозиторий: [oastolyarov/registration-form](https://github.com/oastolyarov/registration-form), у каждой группы своя ветка с одним «посаженным» багом. Здесь исправлен баг в проверке надёжности пароля, а проверка телефона доведена до итогового требования «только +7 и 10 цифр».

## Как запустить

Откройте `index.html` в браузере.

Можно запустить и через локальный сервер:

```bash
python3 -m http.server 8000
```

После этого откройте http://localhost:8000.

## Требования к форме

| Поле | Правило |
|---|---|
| Телефон | Только `+7` и ровно 10 цифр. `+7` уже стоит в поле, вводятся 10 цифр по маске `(999) 123-45-67`. Номер, вставленный целиком (`+7 999…` или `8 999…`), приводится к маске. |
| Пароль | Не короче 8 символов. Обязательно есть строчная латинская буква `a–z`, заглавная `A–Z`, цифра `0–9` и спецсимвол. Допустимы только латинские буквы, цифры и спецсимволы: кириллица и пробелы запрещены. |
| Повтор пароля | Должен совпадать с паролем символ в символ. |

Кнопка «Зарегистрироваться» становится активной, только когда выполнены все три правила.

Спецсимволами считается ASCII-пунктуация: ``! " # $ % & ' ( ) * + , - . / : ; < = > ? @ [ \ ] ^ _ ` { | } ~``.

### Индикатор надёжности

| Индикатор | Когда |
|---|---|
| Надёжный | Выполнены все 5 требований к паролю |
| Средний | Выполнены 3 или 4 требования |
| Слабый | Выполнено 2 требования или меньше, либо в пароле есть кириллица или пробел |

Форма принимает только «Надёжный» пароль. Под полем показан список требований, каждое отмечается галочкой, когда выполнено.

### Сравнение паролей по хэшу

Пароль и его повтор не сравниваются напрямую: от каждого считается SHA-256 через Web Crypto, сравниваются хэши. Заглавная и строчная буква, а также латинская `a` и кириллическая `а` — разные символы Юникода, поэтому дают разные хэши. Значит, `Qwerty1!` и `qwerty1!` не совпадают.

Если браузер не даёт доступа к Web Crypto (страница открыта в небезопасном контексте), пароли сравниваются строгим `===`.

## Что исправлено

**Баг группы 2.** Функция `isPasswordValid` проверяла только длину (`value.length >= 8`). Из-за этого форма принимала пароль `aaaaaaaa`, хотя индикатор сам называл его «Слабым». Теперь пароль принимается, только если выполнены все требования.

Попутно исправлено:

- Кириллица и пробелы засчитывались как спецсимволы: `аааааааа` проходил, а `пароль12` считался «Сильным».
- Пароль из одних цифр (`12345678`) считался «Средним» и принимался.
- Для короткого пароля `Aa1!` индикатор показывал «Сильный» и одновременно ошибку «слишком слабый».
- Телефон принимал `8XXXXXXXXXX`, номера других стран (например `+81 3 1234 5678`) и строки с буквами.
- Сообщение «Регистрация прошла успешно!» не исчезало, если после отправки снова испортить поля. Теперь после регистрации показывается отдельный экран успеха.
- На экранах уже 360px форма вылезала за край, а заблокированная кнопка меняла цвет при наведении.

## Как проверить вручную

| Действие | Ожидаемый результат |
|---|---|
| Набрать в телефоне `89991234567` | В поле `(999) 123-45-67`, номер принят |
| Набрать `99912345` и уйти из поля | Ошибка «Номер неполный: нужно 10 цифр после +7, сейчас 8» |
| Пароль `aaaaaaaa` | Индикатор «Слабый», кнопка заблокирована |
| Пароль `Qwerty12` | Индикатор «Средний», не отмечен спецсимвол |
| Пароль `Пароль1!` | Ошибка «Только латинские буквы, цифры и спецсимволы, без пробелов и кириллицы» |
| Пароль `Qwerty1!`, повтор `qwerty1!` | Ошибка «Пароли не совпадают» |
| Пароль `Qwerty1!`, повтор `Qwerty1!`, телефон заполнен | В поле повтора зелёная галочка, кнопка активна, после нажатия экран «Регистрация прошла успешно!» |

## Структура

```
├── index.html   разметка формы и экрана успеха
├── style.css    оформление: светлая и тёмная тема, адаптив под узкие экраны
├── script.js    логика формы
└── README.md
```

Основные функции в `script.js`:

- `validatePhone`: проверка номера в формате `+7XXXXXXXXXX`;
- `extractPhoneDigits` и `formatPhoneDigits`: маска телефона;
- `getPasswordChecks`, `getPasswordError`, `getPasswordStrength`, `isPasswordValid`: требования к паролю и индикатор;
- `doPasswordsMatch`: сравнение паролей по SHA-256;
- `isFormValid`: общая проверка перед активацией кнопки.
